# 签到和邀请奖励

## 生效规则

- 仅持有当前有效订阅的用户可签到。订阅须已开始、未到期、未暂停/取消，所属订阅分组也须有效。后端在领取事务内校验；资格失效时保留已领取奖励与签到记录。

- 签到按北京时间自然月计算，日历展示当月实际天数（28–31 天）。每天只能领取一次，不补签。
- 每个用户每月基础奖励合计 2500 美分，近似平均随机分配到每天。首次生成后持久化，刷新不会重抽。缺签当天的基础奖励不再补发。
- 连续签到第 7、14、21、28 天各额外获得 200 美分；断签或月初连续天数清零。满勤最高 $33。
- 新注册用户通过有效邀请关系绑定，双方各直接获得 $5 余额。邀请关系、双方奖励流水及余额在同一事务内提交。历史关系不补发。
- 被邀请者兑换 30 天订阅卡（包括默认 30 天的卡）时，邀请者收到同分组 3 天订阅卡。每个原兑换记录最多发放一次。
- 奖励卡在用户邀请页面展示并兑换，仅限邀请者本人使用，奖励卡不会继续触发邀请奖励。
- 原有余额充值返利和在线支付订单返利规则保留。本次新增的订阅奖励针对用户兑换订阅卡，不额外覆盖在线支付订单。

## 接口及账务

- `GET /api/v1/user/checkin`：本月日历、领取状态、累计金额、连续天数。
- `POST /api/v1/user/checkin`：领取当天奖励；重复请求返回当前状态，不重复入账。
- `GET /api/v1/user/aff/reward-cards`：当前用户订阅奖励卡。
- 兑换奖励卡复用现有 `POST /api/v1/redeem`。
- 新增迁移 `250_user_activity_rewards.sql`，新增两张表，不清空任何历史数据。
- `user_activity_rewards` 保存奖励来源、金额、日期和奖励卡关联；`user_checkin_months` 保存每月随机金额计划。
- 签到以用户行锁串行化，奖励流水和余额变动一起提交；注册奖励与邀请绑定一起提交；订阅奖励卡与原卡兑换一起提交。
